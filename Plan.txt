Application

Create a small FastAPI medical appointment service using synthetic test data.

API endpoints
GET  /health
GET  /ready
GET  /appointments
GET  /appointments/{id}
POST /appointments
GET  /simulate-error
Health endpoints
/health confirms that the process is running.
/ready confirms that the application is ready to receive traffic.
/simulate-error returns HTTP 500 for monitoring and troubleshooting practice.
Application requirements
Structured JSON logging
Environment-based configuration
Unit tests with pytest
Datadog APM tracing
No real patient information
Graceful error handling

Important principle

GitHub Actions should not execute:

kubectl apply

GitHub Actions builds and publishes the image. Argo CD performs the deployment using the desired state stored in Git.

Final Demonstration

The completed demo should show:

Terraform creates the Azure infrastructure.
GitHub Actions tests the application.
GitHub Actions builds and pushes the image to ACR.
GitHub Actions updates the image tag in Git.
Argo CD detects the change.
Argo CD deploys the application to AKS.
Datadog receives metrics, logs, and traces.
A simulated error triggers a Datadog monitor.
A Git-based rollback restores the previous version.
Argo CD corrects a manual Kubernetes change.
Interview Explanation

I provisioned the Azure infrastructure with Terraform, including AKS, ACR, Key Vault, managed identities, and role assignments. GitHub Actions runs tests, builds the Docker image, pushes it to ACR, and updates the image version in Git. Argo CD continuously reconciles the Helm configuration from Git and deploys it to AKS. Datadog collects Kubernetes metrics, container logs, and application traces. Application secrets are stored in Azure Key Vault and accessed using AKS Workload Identity.
